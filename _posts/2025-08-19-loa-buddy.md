We want to create a set of tools to figure out market inefficiencies and profit from them in the MMO Lost Ark. 

## Background

Like many other MMOs, Lost Ark has an economy revolving around farming, crafting, and selling items. This market is not remotely efficient, with most people pricing items based on vibes or lowballing for a quick sale. Although opportunities for profit can appear on a lot of various items, we will be focusing on trade skill and crafting items.

The crafting system consists of two main parts, the inputs - trade skill items that players use their life energy to farm for, and the outputs - battle items used in raiding or upgrade materials to hone gear. For the inputs, there are additional systems to convert items of a certain tier to a different one via direct conversion or powder conversion. e.g. 100 timber can be converted to 80 powder, which can then be converted to tender timber at a rate of 100 powder to 50 tender timber, effectively making timber convert to tender timber at a 2.5:1 ratio. If tender timber is more than 2.5 times the price of timber, you can get it cheaper by just buying timber and doing the conversion yourself to get tender timber. Sometimes you can straight up resell the item after converting (market tax permitting) or more commonly, use it as a cheaper input for crafting. To craft items, players have to go through another system, factoring in cost and time reduction percentages on top of input item prices, and then market tax if they plan on selling the crafted item for profit instead of using it themselves.

Because of all the calculations needed to arrive at the optimal price, most players don't even bother, making it historically the most consistent money maker. I've always been drawn towards the idea of using my time and resources as efficiently as possible (min-maxing), so I had created a spreadsheet of these calculations after starting to play the game. However, using the spreadsheet was time consuming, requiring manual input for 30+ items as prices fluctuated.

With the advent of AI coding tools to make up for my lack of front end experience, and with the previous Lost Ark price tracking project shutting down in 2024, it's a good opportunity to create an all-in-one app featuring market calculators and price tracking.

## Goals

- Build out a highly available system to track market prices
- Market data freshness maximum of 8 hours
- Create a user-friendly web app that simplifies complex calculations into simple yes or no answers
- Automatically updates prices for calculations

## Design

The design of LOA Buddy is split into three main parts: an OCR bot to scrape market prices, a backend API to store and retrieve data, and a static web frontend for user interaction.

### Hosting
When I was researching my options for deploying LOA Buddy, there were three that stood out:

- **Self-Hosting**: I have capacity available from self-hosting other applications, so I could spin up another VM for this project. However, there are potential security concerns from exposing my local network to the public internet. My ISP has also been known to randomly go down as well, so it would not meet the high availability target.
- **AWS**: AWS offers super high availability along with a generous free tier, making them a good candidate for hosting small projects like this for free. However, a big downside for me was the lack of usage enforcement. All it takes is one bad actor to spam requests to deplete free tier capacity and rack up the bill. AWS provides ways to prevent this with WAF, but it adds additional complexity and isn't included in the free tier.
*  **Cloudflare**: I eventually settled on using Cloudflare. Similar to AWS, Cloudflare also offers high availability and a free tier. The free tier includes 100k worker requests, 5M rows read, and 100k rows written per day, in addition to free static hosting with pages. There are about 300 items to track with scrapes occurring every hour over two regions, which adds up to ~15k writes and 120 KB stored per day, doubled to ~30k tracking historical prices. The player base is under 20k people so the daily traffic should also be under the free tier limit. Upon hitting the free tier limits, subsequent requests just fail which is fine for a project like this. 

### Market Data Bot
Since Lost Ark does not offer a public API for its market data, I ended up writing a bot that can look through the in-game market and use OCR to extract item name and prices. The bot runs on a VM with an instance of the game, updates the recent price and historical price tables with the new data. This allows it to run 24/7, ensuring data freshness. In addition, every scrape generates metrics sent to a Prometheus server, which alerts me if no successful scrape had occurred in 6 hours. I can then check if the game had crashed and restart it, or if something else went wrong with the scrape. Keeping the alert threshold at 6 hours allows the 8-hour minimum freshness requirement to be met. 

### Backend API
The backend exposes market data APIs, handling both recent and historical market price requests and updates. The API is served by Cloudflare Workers and data is stored in Cloudflare D1, maintaining high availability.

### Frontend
The frontend is a lightweight web application written in Vue.js. The design was created with AI assistance while calculator logic was lifted from my spreadsheet into the app. It features a crafting calculator, arbitrage calculator, and historical price tracking. All calculators allow the user to pull prices directly from the API instead of manually inputting them, and then displays the exact steps to take to achieve the highest profit.

## Learnings

While LOA Buddy's idea and design is straightforward, it was mostly used as a way to familiarize myself with AI and modern coding tools. Gemini CLI and Gemini 2.5 were used when building out this project.

One thing I noticed while working on this is how easily AI will start going off the rails if you let it. It will sometimes start changing semi-related files when it's not necessary or just get stuck, going around in circles. I found that you have to treat it like a junior dev. Be super specific about the task you give it and review its code often. If it does something I don't like, I have it remember by adding a bullet point to the GEMINI.MD file. 

Another thing that I found helps is feeding it information about potentially relevant files before a major change. It doesn't read through all the files, and sometimes the key word search does not paint a complete picture about the project. Maybe even keeping a README updated about all methods that the AI can refer back to would work too.

As a human, I'm not always correct in my review, especially in languages or frameworks I'm not familiar with. When I ask AI about it or suggest changes to the code, the AI very often will agree with me by default and make bad changes even though it was correct in the first place. Telling AI it can disagree usually fixes that problem.
